# ROUND / STACK — 圆角 3D 俄罗斯方块 · 本地对战原型

Godot 4.7.2。保留真正圆角 MeshInstance3D 方块、光滑法线、柔和高光和投影；对战采用真正透视相机，经典单人保留原版相机。与 godot_party_ui 无依赖。

## 运行与模式

用 Godot 4.7.2 导入 project.godot，F5 运行。默认三人个人战。

    Godot_v4.7.2-stable_linux.x86_64 --path /本工程路径
    Godot_v4.7.2-stable_linux.x86_64 --path /本工程路径 -- --team
    Godot_v4.7.2-stable_linux.x86_64 --path /本工程路径 -- --classic

- 个人战：三个独立 10×20 棋盘，同屏同步运行；每个棋盘独立分数、方块袋、HOLD 和道具
- 团体战：两个更宽的 14×20 棋盘，A/B 两队对抗；每队两席共用一个棋盘、分数、HOLD、方块队列和道具。每次成功落定后，队内 SEAT 1 / SEAT 2 轮换；同一时刻每队只有一个活动四连块。当前控制席由会话层跟踪，不再显示席位文字。本地两席使用同一组输入，不是四个并行活动方块
- CLASSIC：保留原来的单人界面。上方向键同样改为硬降，X/Z 旋转；时间加速和成功落定奖励也适用
- 顶出淘汰；剩一人/队时结束并显示赢家；全部淘汰为平局。比赛结束后时间/操作冻结，R 开新局
- 没有机器人，没有联网模块，没有把多块本地棋盘模拟成网络玩家。可单人轮流测试，也可多人共用键盘

1920×1080 设计尺寸，默认窗口 1280×720，按窗口缩放；GL Compatibility + 2× MSAA。无需第三方插件、模型或字体。

## 简洁对战画面

个人战 / 团体战共用深色背景，无外层卡片、窗口或按钮底框。采用 Camera3D.PROJECTION_PERSPECTIVE，相机恢复 0° 正面视角，俯仰、横向偏转和滚转均为零，18° 视场角；仍保留真实透视、方块厚度、圆角和立体光影。棋盘增加克制的立体金属细边框、低对比格子分界线和棋盘之间的细分隔线；凹入底板接收阴影，侧向补光平衡暗部。

棋盘维持紧凑大尺寸布局：子视口高度为 968 设计像素；透视下个人战落块区包围盒高度约 857、团体战约 883 设计像素（在 1180×663 窗口约 526 / 542 像素）；正面视角保持方格的正方形比例。个人战相邻落块区间隔约 32 设计像素，团体战约 36；方块为真实立方体，无非等比拉伸。相机自动拟合完整棋盘体积的八个角点，包含前侧方块和后侧边框，保证顶部与底部不被裁切。保留棋盘宽度和紧凑横向间距，左右分别为按键提示和总计分区保留独立空间。

画面文字只分布在三处：右上角总计分板（按得分排序列出全部玩家/队伍）、每个棋盘正上方的分数、左侧纵向排列的按键提示。不显示标题、模式导航、比赛时钟、速度、底部状态、道具数量、NEXT/HOLD 内容或队内席位。当前棋盘以分数下方的细短色条标记，可点击落块区或用快捷键选择。暂停 / 胜负仅在右上角计分区以极短文字显示，无弹窗；演示局面不叠加演示文字。经典单人场景保留原版布局。

## 操作

F1 / F2 切换个人战 / 团体战，切换直接重开该模式。

| 按键 | 功能 |
| --- | --- |
| 1 / 2 / 3，Tab，点击棋盘 | 选择当前控制的棋盘，细短色条标记；团体战只有 1 / 2 |
| ← / → | 移动当前棋盘，按住连移 |
| ↑ / Space | 硬降并立即落定；不会再触发旋转 |
| X / Z | 顺 / 逆时针旋转 |
| ↓ | 软降 |
| C | HOLD，每个活动方块只允许一次 |
| Q / E | 向左 / 右相邻棋盘发送一个单格干扰方块 |
| , / . | 减少 / 增加干扰目标列，左侧 AIM 提示按 1 开始显示 |
| P / Esc | 全局暂停 / 恢复 |
| R | 清空棋盘、分数、计时和道具，重新开局 |
| F11 | 当前模式的确定性演示局面，画面不加演示标签；P 继续或 R 新局 |
| F12 | 当前模式原生视口截图，覆盖对应截图文件 |

无需切换焦点也可本地多人独立控制：

| 棋盘 | 左 / 右 / 软降 | 硬降 | 顺时针旋转 | HOLD | 快捷攻击 |
| --- | --- | --- | --- | --- | --- |
| 1 / Team A | A / D / S | W | F | G | H → 右邻 |
| 2 / Team B | J / L / K | I | O | U | Y → 左邻 |
| 3（个人战） | 小键盘 4 / 6 / 2 | 小键盘 8 | 小键盘 5 | 小键盘 0 | 小键盘 7 → 左邻 |

中间玩家要攻击右侧可选 2 再 E。快捷攻击使用当前全局目标列。普通数字 1/2/3 与小键盘数字分开。键盘同时按键能力取决于硬件，未加入手柄支持。

经典模式保留 A/D/S、Shift 暂存。窗口失去焦点时自动暂停；暂停不推进比赛计时、重力或锁定计时。

## 时间速度曲线

与消行等级完全独立：只累计未暂停且未结束的比赛时间，所有棋盘使用同一时钟。

    每格间隔 = max(0.065, 0.85 × exp(-比赛秒数 / 110))

约 0s：0.850 秒/格，60s：0.493，120s：0.286，180s：0.166，240s：0.096；约 283 秒达到 0.065 秒/格上限。对战界面不显示计时、速度数字或曲线图，时间加速机制不变。软降间隔 0.035 秒；锁定延迟仍为 0.5 秒，移动/旋转最多重置 15 次。

可在 Godot Inspector 编辑 assets/speed_profile.tres 的 start_interval、minimum_interval、decay_seconds；主场景也暴露 Speed Profile 资源引用。它同时供对战和经典模式使用；曲线绘制脚本保留，可按需复用。

## 计分与道具

- 每次成功落定一个四连块：+10；自然落定与硬降都给，顶出失败不给
- 软降每格 +1，成功硬降每格 +2；落定 +10 另算，即零距离成功硬降仍给 +10
- 消除 1/2/3/4 行：100/300/500/800 × 消除前等级；每累计 10 行提升计分等级
- 每棋盘初始 1 次道具，上限 3；成功消行一次或累计成功落定 5 块，补充 1 次，并重置落定进度。一次落定同时达标只补一次
- 道具是单个橙色格子，从指定目标列顶部落到首个障碍之上，不是整条垃圾行，也不是随机四连块
- 只允许攻击物理相邻的棋盘，不绕过边缘、不跨过中间棋盘；淘汰棋盘不能被攻击，也不会跳过它攻击更远玩家
- 无道具、目标不存在、目标已淘汰、非法列、目标落点与活动方块重叠时，不消耗道具
- 已固定格子堵住目标列最上方时，攻击会令目标顶出并消耗一次道具
- 干扰落点只按已固定棋盘计算，不会固定在正在下落的活动方块上方；如果最终落点与活动方块重叠，本次投放安全拒绝且不消费道具。投放为瞬时插入，无掉落动画；不能覆盖已有格子
- 干扰不会直接加分或补道具，也不会立即消行；完整行待下一次玩家四连块成功落定后正常结算

## 为后续联网预留的边界

scripts/battle_session.gd 是无渲染会话层：

- reset(mode, seed)：新局；固定 seed 可复现各棋盘初始袋序
- submit_action(board_index, action, column=-1)：输入入口，索引和列从 0 开始；支持 left/right/rotate/rotate_back/soft/hold/drop/attack_left/attack_right
- tick(delta, soft_boards)：推进游戏；暂停/结束时冻结。客户端 UI 不应直接改规则状态
- game_event(Dictionary)：递增 sequence、kind、board、比赛 time，并在落定/攻击/结束时附加相应字段
- snapshot()：返回当前棋盘和 UI 状态的深拷贝，适合读取展示/调试；不是可完整恢复 RNG 状态的网络存档

当前无 socket、RPC、房间、鉴权、玩家身份绑定、输入同步、回滚、重连或网络权威裁决。接入时需自行在服务器验证操控权限和团队当前席位，并维护权威时钟、随机数状态和输入序列；不要把本地示范直接当作可上线网络协议。
